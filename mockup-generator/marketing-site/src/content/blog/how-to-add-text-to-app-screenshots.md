## Why text belongs on store screenshots

The UI inside your frame shows *what* the app looks like; overlay text explains *why* it matters. Short headlines bridge that gap—especially in the first screenshot, where many users decide whether to scroll the gallery. Keep copy scannable: one line beats a paragraph, and contrast beats decoration.

Google’s preview-asset guidance warns against misleading claims and dense promotional text. Aim for honest, benefit-led wording that matches what the user will see after install. Screenshots can also appear in **search and discovery surfaces**, not only on your listing—so text must stay readable when the image is small.

## Good vs bad screenshot text examples

| Weak (vague) | Strong (specific) |
|--------------|-------------------|
| "Great UX" | "Swipe to archive mail" |
| "Powerful features" | "Automate repeats in two taps" |
| "#1 app" (unverifiable) | "4.8★ from 12k reviews" (only if true in listing region) |
| Long paragraph | One line + optional subhead |

**Bad patterns:** tiny disclaimers as the hero line, ALL CAPS paragraphs, fake awards, or claims the UI does not demonstrate.

**Good patterns:** verb-led promises, numbers you can defend, and language that matches on-device reality.

## Text placement rules: top, bottom, side, inside frame

- **Top third:** Classic for headlines; keeps thumbs and bottom UI chrome clear. Watch notch / status bar overlap—leave padding.
- **Bottom band:** Works when the top of the UI is busy (maps, media). Avoid covering home-indicator areas in marketing crops.
- **Side margin:** Useful for tablet or desktop frames with wide canvas; pair with shorter copy.
- **Inside the frame (on UI):** Only for callouts that intentionally annotate the screen; keep extremely minimal—never block primary controls.

If you localize, **German and French** often run 20–30% longer at the same font size—pick placement with horizontal slack.

## Font size rules for Play Store thumbnails

1. Export a sheet at the **smallest preview size** you expect (browse, search, or embedded placements).  
2. If the headline is unreadable, **increase size** or **cut words**—do not rely on users opening full screen.  
3. Use **one display family** for headlines across the set; optional second weight for subheads.  
4. Minimum practical sizes depend on canvas resolution; as a rule, **headlines should dominate** decorative elements at thumbnail scale.

## Common mistakes

- **Wall of text** on the first slide—users bounce.  
- **Low contrast** on gradients—beautiful on desktop, illegible in search.  
- **Inconsistent margins** across the set—signals “rushed.”  
- **Localized screenshots** with clipped ascenders/descenders—test each language.  
- **Misleading metrics**—violates policy and hurts retention.

## Step-by-step hierarchy

### Step 1: Choose hierarchy before you write

Decide which screenshots get a headline, which get a subhead, and which rely on UI alone. Feature tours often need text on every slide; minimalist brand shots might use text only on the first and last frames.

### Step 2: Align text to the frame and safe area

Keep headlines inside a consistent margin band (top or bottom third is common). Leave padding so store chrome or rounded corners do not clip letters.

### Step 3: Test at thumbnail size

Export a contact sheet at browse-view scale. If the headline fails, iterate size and copy together—not one at a time.

### Step 4: Match tone across Play and App Store

Reuse phrasing where possible so brand voice stays consistent when dimensions differ. Compare policies in [Play Store vs App Store screenshots](/blog/play-store-vs-app-store-screenshots/).

## Final checklist

- Every headline true to the product  
- Contrast checked on light and dark backgrounds  
- Thumbnail legibility verified  
- Localization planned before locking layout  
- Internal story order matches your onboarding truth  

## FAQ

### Should every screenshot have text?

No. Use text where it clarifies value; let clean UI shots breathe where the screen is self-explanatory.

### How much text is too much?

If text covers a large fraction of the canvas or competes with the UI, simplify. Keep taglines **short** relative to the overall image.
